# EpicFundamental — рабочая памятка

Фундаментальный анализ крипты для стратегии «лесенки»: когда ротировать BTC → альты,
в каком порядке входить, когда выходить из всего в стейблы. Личный инструмент одного
пользователя. Подробности источников — в README.md, здесь только то, что нужно для работы.

## Стек и запуск

Next.js + FastAPI + SQLite. Бэкенд `backend/app`, БД `backend/data/epicfundamental.db`,
фронт `frontend`, статический экспорт → gh-pages.

```
cd backend; .venv\Scripts\python -m pytest tests -q     # 75 тестов, должны быть зелёные
.venv\Scripts\python -m app serve                        # API :8000
cd frontend; npm run dev                                 # :3000
.\update_daily.ps1 -Force -NoDeploy                      # ручной дневной прогон
.\deploy.ps1                                             # экспорт + сборка + публикация
```

Команды CLI: `sync, backfill, update, screen, backtest, notify, ladder, list-collectors, serve, export`.
Сайт: https://cryptoandy1.github.io/EpicFundamental/ (Pages собирает коммит 1–2 мин).

## Две независимые системы решений (не смешивать)

1. **Ворота входа** (`_entry_gate` в main.py) — когда ротировать BTC в альты.
   Открыты, если доля топ-100, обгоняющих BTC за 30 дн., ≥ порога И доминация BTC падает
   (среднее последних 7 точек против среднего 7 точек 28 дн. назад; на разреженных данных
   откат к двум точкам). Состояния: `closed | warming | open`. warming = альты выше порога,
   но доминация не подтверждена. Пороги: `config/projects.yaml → entry_gate`.
2. **Сигнал выхода** (`_exit_signal`) — когда продавать ВСЁ в стейблы.
   Два независимых источника, срабатывает любой: Google Trends «bitcoin» ≥ 90 перцентиля
   за 5 лет ИЛИ Coinbase ≤ #10 в общем топе App Store. Разогрев при 75 / #50.
   Уровни `ok | warming | sell`. Пороги: `config/projects.yaml → exit_signal`.
3. **Playbook** (`_playbook`) сводит оба в одну строку: EXIT > ROTATE > HOLD_BTC.

## Лесенка

15 факторов, сумма |весов| 13.0, веса в `config/projects.yaml → scoring`.
Каждый фактор → перцентиль по пулу → взвешенная сумма. Отрицательный вес = штраф.
**Фактор без данных = нейтральные 50 с полным весом** (не выпадает из знаменателя),
доля веса на реальных данных возвращается как `coverage` — всегда смотреть вместе со скором.

Пул (9, утверждён вручную): solana, celestia, near, avalanche, sui, aptos, sei, injective, bittensor.

## Что проверено бэктестом (важно для любых выводов)

`python -m app backtest` — скор считается as-of (без знания будущего) и сверяется
с последующей доходностью. На 2024-01…2026-08, 35 периодов по 28 дней:

| | |
|---|---|
| Верх лесенки минус низ | +4.9% за период, плюс в 57% периодов |
| Spearman (ранг vs доходность) | среднее +0.11, медиана +0.20 |
| Топ-3 накопленным итогом | −32% против +79% у HODL BTC |

**Вывод: скор ранжирует альты верно, но ротация в альты проигрывала биткоину** —
2024–2026 были сезоном биткоина. Лесенка отвечает «в какую монету», ворота — «пора ли
вообще из BTC». Главная метрика качества — лонг-шорт (нейтральна к фазе рынка),
не доходность против BTC. Ограничения живут в `summary.caveats` (survivorship bias пула,
снапшотные факторы только с 08.2026, комиссии на сделки не учтены).

## Автообновление

`update_daily.ps1` / `update_weekly.ps1`, общая обвязка `update_common.ps1`
(Write-Log, Invoke-Step, Send-Alert, Enter/Exit-UpdateLock, Complete-Run).
Триггеры: выход из сна (+3 мин дневной, +8 мин недельный) и время (18:00 / вс 19:00).
Отметки `backend/logs/*.stamp` держат ритм: один дневной в день, один недельный в неделю
(догон на 8-й день). Недельный ставит и дневную отметку.

**Дневной** (~9 мин, 8 кредитов Nansen): цены, BTC, ноды, DefiLlama, ранг Coinbase,
altseason (ворота), лёгкий Nansen → export → notify → deploy.
**Недельный** (~25 мин): всё то же + GitHub, Trends, GDELT, разлоки, кошельки, Discord,
полный Nansen + screen + backtest.

Снапшотные метрики (Nansen, ноды, Coinbase, доминация) **нельзя добрать задним числом** —
пропущенный день потерян навсегда. Остальное (цены, DefiLlama, GitHub, Trends) восстанавливается
любым прогоном: `update()` по умолчанию = `backfill()`, всё идемпотентно через upsert.

## Главный урок проекта: автономный сбор обязан кричать

19.08–22.09.2026 прогоны падали 35 дней подряд, Планировщик показывал успех, сайт стоял.
Три молчаливых сбоя: `print()` кириллицы в пайп (cp1252), истёкший GITHUB_TOKEN (401 с
отчётом «0 точек»), кулдаун GDELT (90 минут вхолостую). Отсюда действующие правила:

- скрипты выходят с кодом 1 при сбое + `LAST_FAILURE.txt` + алерт (Telegram/msg.exe);
- `meta.json` отдаёт `stale` со своим допустимым возрастом у каждой метрики, бейдж краснеет;
- `python -m app notify` шлёт переходы (ворота, выход, протухание источника) и воскресную сводку;
- любой коллектор с внешним API имеет предохранитель от бесконечных ретраев.

**Свежий экспорт не означает живые данные.** Проверять: `backend/logs/*.stamp`,
`LAST_FAILURE.txt`, `signals_state.json`, `(Get-ScheduledTaskInfo -TaskName "EpicFundamental*").LastTaskResult`.

## Открытые проблемы (по убыванию важности)

1. **Недельный прогон не отрабатывал с 27.09** — замок, добавленный против одновременной
   записи в SQLite, детерминированно душит его: триггеры недельного (сон+8 мин, вс 19:00)
   попадают в окно работающего дневного, тот возвращается сразу и ждёт ещё неделю.
   Последствие: `trends_weekly` и `github_*` протухли с 20.09, **сигнал выхода считается
   по данным месячной давности**. Чинить: ждать освобождения замка с таймаутом (~30 мин)
   вместо мгновенного выхода, либо разнести триггеры. Протухание система видит и сообщает.
2. Замок регулярно остаётся «протухшим» (возраст 21 ч) — прогоны убиваются на середине,
   вероятно уходом компьютера в сон. Перехват работает, но часть прогонов не доходит до конца.
3. GDELT (`media_mentions`) — 0 точек, кулдаун по IP. Повторять `update --collector mentions`
   в другой день; интервал 6 с в `base.py` не уменьшать.
4. Ключи `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` не заведены — notify печатает в лог.
   Рецепт: @BotFather → /newbot → токен; написать боту /start; `getUpdates` → chat.id.
5. Нет факторов выручки протокола (DefiLlama `dailyRevenue`) и притоков ETF — именно ими
   двигались лидеры 2026 (HYPE, ZEC). Это главный содержательный пробел.
6. Пустые факторы (вес 3.0 из 13.0): mentions, discord (нет DISCORD_TOKEN), team_selling
   (кошельки команды не заведены, коллектор видит только ERC-20 tokentx).

## Решения пользователя (не выводимы из кода)

- Стек менять нельзя; новые источники — опционально через env.
- Пул утверждается вручную в `config/projects.yaml`; скринер только предлагает.
- HYPE и ZEC в пул **не добавлять** — только watch-list (`screener.always_include`).
  HYPE: нет пары на глобальном Binance, ядро закрыто, разлок 9.92M ежемесячно до конца 2027.
  ZEC: прошёл фильтры, но вход после утроения цены — покупка параболы.
- Nansen Pro: кредиты это **разовый грант** (~1969 осталось), не месячный. Беречь.
- DefiLlama Pro не покупаем: raises/emissions вводятся вручную.
- Discord-экспорт своим токеном: ToS-риск проговорён, пользователь согласен.
- GitHub Actions не использовать: у токена нет scope `workflow`.

## Ловушки окружения

- `.ps1` запускаются Windows PowerShell 5.1 (pwsh нет). Сохранять **UTF-8 с BOM**, иначе
  кириллица в комментариях ломает парсер. `$ErrorActionPreference = "Continue"` + проверка
  `$LASTEXITCODE`: `2>&1` на нативном exe при `Stop` рвёт скрипт на обычных WARNING питона.
- Python под Планировщиком пишет в пайп как cp1252 → кириллица в `print()` падает.
  Защита на двух уровнях: `_utf8_streams()` в cli.py и `$env:PYTHONUTF8=1` в скриптах.
- Bash-heredoc в этой среде ломается на длинных Python-вставках — для крупных правок
  использовать Write/Edit, а не `python - <<'PY'`.
- CoinGecko жёстко 429-ит, если недельный прогон идёт сразу за дневным.
- `backend/.env`, `backend/data/`, `backend/logs/`, `tools/` — в .gitignore.

## Соглашения кода

- Комментарии и сообщения — по-русски, объясняют **почему**, а не что (код виден).
- Любой новый фактор: сразу решить, что будет у монет без данных, и покрыть тестом.
- Новый шаг в прогоне подключается нефатально: `Invoke-Step ... | Out-Null`.
- Коммиты: заголовок по-русски, в теле — причина и последствие, а не перечисление файлов.
